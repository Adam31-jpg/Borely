🚀 MASTER SPECIFICATIONS : PLATEFORME HUB MICRO-SAASVersion : 1.0Statut : Document de Référence (Source of Truth)Objectif : Cadrage complet pour le développement d'un écosystème de Micro-Apps modulaires.📂 DOCUMENT 01 - BLUEPRINT : VISION & EXPÉRIENCE PRODUIT (PRD)Note au développeur : Ce document définit les objectifs métier et l'expérience utilisateur. Tu es invité à le réviser et à proposer des optimisations techniques (ex: performance, accessibilité) avant toute implémentation. Si une contrainte technique majeure entre en conflit avec l'UX décrite, elle doit être signalée immédiatement.1. Vision du ProduitL'idée est de créer une plateforme centralisant plusieurs micro-applications payantes, chacune effectuant une tâche spécifique pour simplifier la vie de l'utilisateur.Simplicité : Zéro friction. Un achat = un accès immédiat. Pas de système de crédits.Modularité : Chaque application est indépendante mais cohabite dans un hub central.Esthétique : Design "Apple-like", épuré, typographies soignées, transitions fluides. On ne veut pas que ça "fasse IA", mais "Designer Humain Pro".2. Parcours Utilisateur (User Flow)L'utilisateur doit pouvoir naviguer entre trois états principaux :A. Le Store (Marketplace)Vue d'ensemble : Une grille d'applications avec icônes pro, titre, courte description et prix.Fiche Produit : Vidéo/GIF de démonstration, bénéfices clairs, bouton d'achat direct via Creem.io.Filtrage : Possibilité de filtrer par catégorie (Productivité, Finance, Privacy).B. La Bibliothèque (My Apps)Espace personnel listant uniquement les applications déjà achetées.Accès rapide en un clic sans repasser par le store.C. L'Espace Micro-AppChaque application s'ouvre dans le hub mais occupe tout l'espace utile.Interface spécifique à la tâche (ex: liste d'expéditeurs pour l'app Mail).Navigation persistante (Sidebar ou Topbar) pour revenir au Store ou changer d'app.3. Design & Interface (UI/UX)Thème : Dark Mode par défaut (Gris très sombres, pas de noir pur #000000). Bouton de switch Light Mode disponible.Mobile-First (PWA) :L'application est un site internet mais doit fonctionner comme une app native.Bouton d'installation : Prévoir un bouton explicite pour créer une icône sur l'écran d'accueil du téléphone (PWA Manifest).Support des gestes tactiles (swipe) pour la navigation.Identité : Chaque micro-app possède sa propre "accent color" (ex: Bleu pour le Mail, Vert pour la Banque) injectée dans les composants partagés.Fluidité : Utilisation systématique de Skeleton Screens. Aucune page blanche ne doit apparaître.4. Stratégie de Paiement (Creem.io)Pas de crédits : L'utilisateur paye l'app directement. Paiement simple et efficace.Modèles : Achat unique (Lifetime) ou Abonnement selon l'app (défini par le Product ID Creem).Déblocage : Une fois le webhook de paiement reçu, l'accès à l'app est débloqué instantanément dans le profil utilisateur.5. Règles d'Or pour le DéveloppementIA Invisible : L'IA (Gemini) travaille en backend pour la logique. L'interface reste déterministe et humaine.Scalabilité : Le système doit pouvoir accueillir 100 micro-apps sans alourdir le Core.Privacy : Ne récupérer que le strict minimum. Pour l'app Mail : interdiction de stocker le corps des emails.💡 CHALLENGE DÉVELOPPEUR N°1 : Comment comptes-tu gérer la transition entre les applications pour que l'expérience reste fluide (SPA) sans rechargement lourd de toute la plateforme ?📂 DOCUMENT 02 - SPÉCIFICATIONS TECHNIQUES & ARCHITECTURE (TDD)1. Stack TechnologiqueFramework : Next.js (App Router) avec Turborepo (Monorepo).Langage : TypeScript (Mode strict).Style : Tailwind CSS + shadcn/ui.Gestion d'état : TanStack Query (React Query) pour le cache.Base de données : PostgreSQL (via AWS RDS).ORM : Prisma ou Drizzle.2. Structure du Monorepo (Modularité)Le code doit être hyper modulaire. Les composants doivent être réutilisables et customisables via des paramètres (props).Plaintext/apps
  ├── /hub          # Le portail (Store + Bibliothèque + Auth + Billing)
  ├── /app-mail     # Micro-app : Désabonnement (Module isolé)
  └── /app-finance  # Micro-app : Banking (Futur module)
/packages
  ├── /ui           # Bibliothèque de composants (Boutons, Inputs, Cards)
  ├── /database     # Client DB & Schémas partagés
  ├── /auth         # Logique de session (NextAuth / Cognito)
  └── /config       # Config ESLint, Tailwind, TypeScript
3. Architecture Cloud (AWS)Utilisation du compte AWS existant. Priorité au Serverless.Hosting : AWS Amplify Hosting ou Vercel.Compute : AWS Lambda pour les tâches de fond (scans de mails, appels API banques).Scheduling : Amazon EventBridge pour les tâches planifiées (ex: scan tous les 14 jours).Auth : AWS Cognito couplé à NextAuth.js. Support de Google Login obligatoire.Secrets : AWS Secrets Manager pour les clés d'API (Gemini, Creem, Google).4. Stratégie de Base de Données (Multi-Schema)Une seule instance RDS pour limiter les coûts, mais isolation stricte :Schema public : Tables globales (users, subscriptions, apps_catalog).Schema app_mail : Tables spécifiques (scanned_senders, blacklist).Règle : Une app n'écrit jamais dans le schéma d'une autre.5. Implémentation Mobile & PWAService Workers : Cache agressif pour la vitesse.Manifest.json : Configuration des icônes et splash screens.Logic d'installation : Création d'un composant détectant l'OS pour guider l'utilisateur sur comment ajouter l'icône sur son téléphone.6. Intégrations IA (Gemini Pro)Modèle : gemini-1.5-flash via Google AI Studio (Coût réduit/Rapidité).Usage : Catégorisation intelligente (ex: différencier un abonnement d'un loyer dans les relevés bancaires).💡 CHALLENGE DÉVELOPPEUR N°2 :Comment sécuriseras-tu les tokens OAuth de Google en base de données (Chiffrement au repos via AWS KMS recommandé) ?Propose un workflow CI/CD pour déployer app-mail sans toucher au hub.📂 DOCUMENT 03 - DESIGN SYSTEM & UI SPEC (THE UI BIBLE)1. Principes "Humain Pro"Whitespace : Aérer les interfaces. Ne pas surcharger.Radius : Arrondis généreux (rounded-xl ou 2xl) pour un aspect moderne.Transitions : Utilisation de Framer Motion. Durée : 200-300ms. Transitions fluides entre les vues.Hiérarchie : Utiliser le contraste (bold vs muted) plutôt que de multiplier les tailles de police.2. Bibliothèque de Composants (@shared/ui)Chaque composant doit être un "atome" réutilisable.Exemple : Le composant Button doit prendre un paramètre appContext pour changer sa couleur selon l'app où il se trouve.Composants prioritaires : Layout Wrapper, App Card, Action Bar (flottante en bas sur mobile), Skeleton Loaders, Empty States.4. PWA UI & NavigationZones tactiles : Minimum 44x44px pour chaque bouton.Desktop : Sidebar à gauche ou droite (rétractable).Mobile : Tab bar en bas (Home, Store, Settings) pour navigation au pouce.PWA Prompt : Popup stylisée pour iOS et Android (instruction "Ajouter à l'écran d'accueil").5. TypographiePolices : Inter ou San Francisco (Polices système).Règles : Titres en font-semibold avec letter-spacing réduit.
